# GAS & スプレッドシート永続化アーキテクチャ

## 1. スプレッドシート 11カラム仕様

シート名: `プレイ記録`

| 列番号 | カラム名 | データ型 / 内容 | 説明 |
| :---: | :--- | :--- | :--- |
| **A (1)** | 最終更新日時 | Date | 日本時間タイムスタンプ |
| **B (2)** | 名前（カタカナ） | String | 生徒の登録名（全角カタカナ推奨） |
| **C (3)** | パスコード | String (`'XXXX`) | 4桁数字（文字列として先頭ゼロ欠落防止） |
| **D (4)** | 現在主人公 | String | 例: `A: レン（自由権）` |
| **E (5)** | 現在地（シーン名） | String | 例: `10:00 首輪の火花` |
| **F (6)** | 達成度 | String | 例: `5 / 23 結末解明` |
| **G (7)** | 復帰キー | String | ノードID（例: `A_1000`） |
| **H (8)** | 獲得フラグJSON | JSON String | `["A_HOUR1_CLEAR", ...]` |
| **I (9)** | 通過ノードJSON | JSON String | `["A_1000", "A_1015", ...]` |
| **J (10)** | 解放結末JSON | JSON String | `{"BAD_A_01": true, ...}` |
| **K (11)** | スロット状態JSON | JSON String | `{"A_1000": "A", ...}` |

## 2. 二重保存・耐障害フォールバック (Dual-Layer Sync)

授業中のWi-Fi切断や生徒の一斉アクセスによるGAS遅延に対応するため、フロントエンド（`js_state.html`）は以下の設計になっています：

1. **第1層：ローカルストレージ即時保存 (`saveLocal()`)**
   - 画面遷移、選択肢選択、BAD END到達の瞬間にミリ秒単位で `localStorage` に保存。
   - 通信が切断されても、生徒のブラウザ上では何の影響もなくプレイを続行可能。
2. **第2層：非同期サーバー同期 (`syncServer()`)**
   - ノード遷移時にバックグラウンドで `google.script.run.saveProgress(data)` を呼び出し。
   - サーバー混雑中（LockService待機）やエラー時でもゲーム画面を停止・ポップアップで阻害しない非ブロッキング仕様。

## 3. LockService による排他制御

`Code.js` 内の書き込み処理はすべて `LockService.getScriptLock()` でラップされています。

```javascript
const lock = LockService.getScriptLock();
try {
  lock.waitLock(30000); // 30秒間ロック取得を待機
  // スプレッドシート読み書き処理
} finally {
  lock.releaseLock();
}
```

- クラス30〜40人が同時に名前登録・セーブを実行しても、行の重複や上書き破壊が発生しません。
